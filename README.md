# 📸 一切皆可 Skill：AI 修图指令生成器，让修图像复制粘贴一样简单

## 前言

作为一个摄影爱好者，我经常遇到这样的场景：

> "这张照片好好看！怎么调出来的？"

然后就是一顿操作——打开 Lightroom，调曝光、拉曲线、改色温……半小时过去了，效果还不一定好。

后来 AI 修图工具火了，豆包、美图秀秀都能一键修图。但问题来了：

> **AI 修图工具听不懂"专业摄影语言"。**

你说"帮我加 0.5EV 曝光补偿，高光压 -30，阴影提 +20"，它一脸懵。你说"帮我修好看点"，它给你来个美颜滤镜大杂烩。

**这就是我创建 photo-style-transfer Skill 的初衷——在「专业摄影知识」和「AI 修图工具」之间搭一座桥。**

---

## 一、核心思路：不修图，生成修图指令

一开始我想的是让 AI 直接修图。但 TRAE SOLO 的能力边界告诉我：**与其做一个不完美的修图工具，不如做一个完美的修图指令生成器。**

工作流很简单：

```
用户上传照片
    │
    ▼
AI 分析照片特征
（构图、光线、色调、景深、问题诊断）
    │
    ▼
生成结构化修图指令
（用代码块包裹，一键复制）
    │
    ▼
用户复制 → 粘贴到豆包 → 获得专业修图效果
```

**核心价值**：AI 不需要会修图，它只需要「懂」修图。把专业的摄影参数翻译成 AI 修图工具能理解的指令，这就是这个 Skill 做的事。

## 二、Skill 结构设计

### 2.1 目录结构

```
photo-style-transfer/
├── SKILL.md                      # 入口文件（YAML元数据 + 工作流）
├── references/                   # 参考文档（按需加载）
│   ├── photography-basics.md      # 摄影参数基础知识
│   ├── lens-guide.md              # 镜头选择指南
│   └── usage-examples.md          # 修图指令生成示例
└── assets/                       # 模板资源
```

### 2.2 SKILL.md 的关键设计

**YAML description 是触发入口**，必须覆盖所有可能的用户表达：

```yaml
description: "AI修图指令生成器。当用户需要：上传照片后获取专业修图建议
和操作指令；分析照片的摄影参数（镜头、光圈、快门、ISO、光线、构图）；
生成可直接复制到豆包/美图秀秀等AI修图工具的修图提示词；获取特定摄影风格
（85mm人像、风光、街拍等）的后期调色参数。触发词包括：帮我修图、分析照片
参数、生成修图指令、这张照片怎么调、修图建议、摄影参数分析、调色指令、
豆包修图。"
```

**工作流分三步**：
1. **读取图片** → 用 Read 工具分析照片特征
2. **匹配模板** → 根据场景类型选择修图模板
3. **生成指令** → 输出代码块包裹的修图指令

### 2.3 渐进式知识加载

这是 Skill 设计中最重要的理念：

- **SKILL.md**（~400行）：只放工作流、模板、速查表
- **references/photography-basics.md**：详细摄影知识（按需加载）
- **references/lens-guide.md**：镜头选择指南（按需加载）
- **references/usage-examples.md**：5 个完整示例（按需加载）

AI 先读 SKILL.md 获取工作流，遇到不确定的参数时再按需加载 references，不浪费 Token。

## 三、修图指令模板系统

### 3.1 四大场景模板

| 模板 | 适用场景 | 关键特征 |
|------|----------|----------|
| A：人像精修 | 人像特写、环境人像 | 肤色优化、背景虚化、面部保护约束 |
| B：风光大片 | 风景、建筑、旅行照 | 高对比、高饱和、通透感 |
| C：街拍纪实 | 街拍、日常、人文 | 胶片感、颗粒、真实感 |
| D：夜景低光 | 城市夜景、灯光 | 蓝调、降噪、灯光氛围 |

### 3.2 四大风格预设

| 预设 | 风格 | 关键参数 |
|------|------|----------|
| 85mm 人像 | 经典人像 | 浅景深、奶油虚化、暖色调 |
| 电影感 | 电影调色 | 青橙色调分离、暗角、高对比 |
| 日系清新 | 日系风 | 低对比、低饱和、明亮通透 |
| 胶片复古 | 复古风 | 颗粒感、偏色、漏光效果 |

### 3.3 问题 → 修正映射表

AI 分析照片后，会自动诊断问题并生成修正指令：

| 问题 | 修正指令 |
|------|----------|
| 过曝 | 曝光 -0.5~-1.5EV，高光 -30~-50 |
| 欠曝 | 曝光 +0.5~+1.5EV，阴影 +20~+30 |
| 偏黄 | 色温向冷偏移，降低橙色饱和度 |
| 灰蒙蒙 | 对比度 +15~+25，饱和度 +10~+20 |
| 噪点多 | 降噪强力，轻微柔化 |

## 四、实战演示

### 演示 1：自动分析 + 生成修图指令

**用户操作**：上传一张古镇雪山照片，说"修图"

**AI 输出**：

```
【照片分析】
- 构图：框架式构图 + 三分法
- 光线：侧逆光，暖色调
- 景深：中等偏深（f/5.6-f/8）
- 问题：对比度偏低、阴影细节不足、饱和度偏低
→ 匹配模板 B（风光大片）

【修图指令 - 复制以下内容到豆包】
请对这张照片进行以下调整：
【基础调整】
- 曝光：+0.3EV
- 对比度：+15（去除灰蒙蒙感）
- 高光：-30（恢复云层细节）
- 阴影：+25（提亮古镇暗部）
...
```

用户复制代码块内容 → 粘贴到豆包 → 完事。

### 演示 2：指定风格修图

**用户输入**："帮我用胶片感修这张街拍"

**AI 输出**：

```
→ 匹配模板 C（街拍/纪实）+ 预设 4（胶片复古）

【修图指令 - 复制以下内容到豆包】
请对这张街拍照片进行以下调整：
【色彩调整 - 胶片感】
- 饱和度：-10（胶片低饱和特征）
- 色调分离：高光偏绿，阴影偏橙
【风格化 - 胶片复古】
- 添加中等颗粒感（模拟ISO 400胶片）
- 添加轻微漏光效果
...
```

### 演示 3：人像精修 + 身份保护约束

**用户输入**：上传人像照片，说"帮我精修"

**AI 输出的修图指令中包含严格的约束条件**：

```
【约束】
- 严格保持人物面部特征和表情不变
- 不改变面部形状和五官位置
- 不替换或修改背景内容
- 仅做肤色优化和光影调整
```

这些约束会被写入修图指令中，豆包在执行时会遵守这些限制。

## 五、踩坑与经验总结

### 踩坑 1：description 决定触发率

最初我的 description 太简单：

```yaml
# ❌ 触发率极低
description: "修图建议"
```

改成覆盖多种表达后，触发率大幅提升：

```yaml
# ✅ 触发率显著提高
description: "AI修图指令生成器。当用户需要：上传照片后获取专业修图建议
和操作指令；分析照片的摄影参数...触发词包括：帮我修图、分析照片参数、
生成修图指令、这张照片怎么调..."
```

**经验：description 要包含用户可能说的所有话，不只是功能描述。**

### 踩坑 2：修图指令必须用代码块包裹

最初我直接输出修图指令文本，用户复制时总会带上前面的分析报告。

改成代码块后：

````markdown
修图指令（复制以下内容到豆包）：
```text
请对这张照片进行以下调整：
...
```
````

用户一键复制代码块内容，干净利落。

### 踩坑 3：约束条件比修图参数更重要

AI 修图工具最大的问题是"过度发挥"——你让它修人像，它把你的脸都换了。

所以在每个修图指令模板中都加入了**约束条件**：

- 人像：不改变面部特征和表情
- 风光：不添加或删除画面元素
- 街拍：保持纪实真实感
- 夜景：不改变灯光位置和颜色

**这些约束是修图指令的核心价值之一。**

### 踩坑 4：从"生成图片"到"生成指令"的转型

最初我做的是图像生成 Skill，依赖 GenerateImage 工具。但后来发现：

1. 不是所有 TRAE 用户都有 GenerateImage 工具
2. 生成新图片 ≠ 修图（用户要的是修自己的照片）
3. 指令生成是更通用的方案（适用于豆包、美图秀秀、任何 AI 修图工具）

**转型后，Skill 的适用范围反而更广了。**

## 六、Skill 的价值

### 对用户的价值

| 场景 | 没有 Skill | 有 Skill |
|------|-----------|----------|
| 修图 | 盲调参数，效果随机 | AI 分析照片，精准生成指令 |
| 学摄影 | 知识碎片化，不成体系 | 结构化知识 + 实战示例 |
| 风格模仿 | 不知道怎么调 | 一键生成指定风格的修图指令 |

### 对 AI 生态的价值

这个 Skill 证明了一个重要理念：

> **Skill 的本质不是让 AI 做更多事，而是让 AI 在特定领域做得更专业。**

修图指令生成器不需要 GenerateImage，不需要 Photoshop API，不需要任何图像处理工具。它只需要：
- **Read 工具**（分析图片）
- **结构化知识**（摄影参数 + 修图模板）
- **文本输出**（代码块包裹的修图指令）

**一切皆可 Skill，不是一切皆可生成，而是一切领域知识皆可结构化。**

---

## 七、总结

photo-style-transfer 的核心价值：

1. **桥梁作用**：在专业摄影知识和 AI 修图工具之间建立桥梁
2. **零门槛**：用户只需上传照片，复制指令，粘贴到豆包
3. **专业性**：基于真实摄影参数和后期修图经验
4. **通用性**：生成的指令适用于任何 AI 修图工具
5. **约束保护**：防止 AI 修图工具"过度发挥"

从"让 AI 修图"到"让 AI 生成修图指令"，这个转变让 Skill 从一个受限的工具变成了一个通用的修图助手。
